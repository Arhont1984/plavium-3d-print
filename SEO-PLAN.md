# План SEO-насыщения сайта ПЛАВИУМ

Составлено 2026-07-27. Приоритизация — что даёт максимум эффекта в Яндекс.Поиске при
минимуме рисков, и что можно делать параллельно. Актуальный статус того, что уже сделано
и что ещё предстоит — см. «Незаполненные места» в [CLAUDE.md](CLAUDE.md), этот файл —
именно про стратегию продвижения, а не про техническое состояние проекта.

## Фаза 0 — Технический фундамент (сделать в первую очередь, разово)

Без этого остальной контент не будет нормально индексироваться.

1. **Домен и хостинг** — `plavium.ru` пока не зарегистрирован. Без реального домена на
   боевом хостинге нет смысла активно наращивать контент — переезд с GitHub Pages потом
   потребует пересборки внутренних ссылок и потери временно накопленных сигналов.
2. **Яндекс Вебмастер** — подтвердить домен, отправить sitemap.xml (уже генерируется
   автоматически, `@astrojs/sitemap`), включить индексацию через API или ручную отправку
   урлов для ускорения.
3. **Яндекс Метрика** — вебвизор + карта кликов важны сразу: Яндекс использует поведенческие
   факторы (время на сайте, глубина просмотра, возвраты в выдачу) как один из сильнейших
   сигналов ранжирования.
4. **Яндекс Бизнес / Карты** — профиль компании с адресом, телефоном, часами работы, фото —
   критично для локального SEO и для расширенного сниппета в выдаче (рейтинг, отзывы прямо
   в поиске).
5. **Реальные NAP-данные** (Имя-Адрес-Телефон) в `src/data/site.ts` — сейчас заглушки, а
   Яндекс сверяет консистентность данных на сайте, в Бизнесе и в других источниках
   (справочники, 2ГИС).
6. **Решить гео-стратегию** — только Москва (тогда усиливаем локальное SEO, возможны
   гео-страницы районов) или вся Россия (тогда упор на информационные и транзакционные
   запросы без региональной привязки, доставку — в основной текст, без гео-дублей).

## Фаза 1 — Контент, который сейчас даёт максимум трафика при минимуме усилий

7. **Реальные фото и тексты в портфолио** — сейчас все 3 кейса в `src/content/portfolio/`
   черновики. Уникальный контент с фото — сильный сигнал качества для Яндекса
   (антидубль-фильтр), а для конверсии — главный фактор доверия в нише «печать на заказ».
   Каждый кейс — отдельная проиндексированная страница с уникальным текстом 200–400 слов.
8. **Отзывы** — раздела нет вообще. Синхронизация с Яндекс.Картами/2ГИС (виджет или ручной
   перенос) — в услугах один из сильнейших факторов доверия и поведенческих метрик (дольше
   держат пользователя на странице).
9. **Прайс-лист** — цены сейчас нигде не указаны. Даже ориентировочная сетка («печать
   детали от N ₽/см³», «фигурка от N ₽») закрывает большой пласт транзакционных запросов
   вида «3d печать цена».

## Фаза 2 — Расширение семантики через новые страницы

Аналогично тому, как в «братском» проекте WashFix страницы брендов/районов масштабировали
SEO из структурированных данных, здесь такой же приём — но через материалы и типы изделий.

10. **Страницы материалов** — PLA, PETG, ABS, нейлон, фотополимерные смолы
    (стандартная/прочная/гибкая). Каждая — отдельный лендинг: свойства, для чего подходит,
    примеры из портфолио. Закрывает информационные + транзакционные запросы («печать
    нейлоном», «деталь из petg на заказ»).
11. **Страница подготовки модели** — форматы файлов (STL/OBJ/STEP), как подготовить модель,
    допуски. Закрывает запросы от инженерной аудитории.
12. **Блог по симптомам спроса** — самый крупный потенциальный источник трафика по объёму
    запросов, но и самый трудоёмкий: «сколько стоит напечатать фигурку», «FDM vs
    фотополимер для начинающих», «как заказать 3D-печать первый раз», «почему деталь
    получилась хрупкой» и т. п.
13. **Расширить `/oborudovanie/`** реальными фото принтеров и конкретными моделями — сейчас
    общее описание технологий, а не оборудования компании.

## Фаза 3 — Локальные и коммерческие сигналы

14. **Коммерческие факторы Яндекса** (если гео = Москва) — реальные юридические данные
    (ИНН/ОГРН, сейчас заглушки), способы оплаты, гарантии, сроки — Яндекс ранжирует такие
    «факторы коммерциализации» отдельно для транзакционных запросов.
15. **Микроразметка Schema.org** — уже есть `LocalBusiness` и `FAQPage`. Добавить
    `Product`/`Offer` на страницы услуг с ценами, `Review`/`AggregateRating` когда появятся
    отзывы, `BreadcrumbList` для хлебных крошек (сейчас визуально есть, но не размечены как
    structured data).
16. **Скорость и Core Web Vitals** — реальные фото портфолио и логотипа продолжать
    оптимизировать через Sharp (как уже сделано для бренд-баннера в
    `scripts/optimize-brand-images.mjs`) — Яндекс тоже учитывает скорость загрузки.

## Фаза 4 — Внешние сигналы (когда сайт уже наполнен)

17. **Тематические каталоги/агрегаторы** услуг 3D-печати, профиль на Авито/Юле как
    дополнительный канал (не столько SEO, сколько трафик + косвенный сигнал доверия).
18. **Естественные ссылки** — публикации о выполненных проектах на профильных
    форумах/пабликах (например, кейс для Сбербанка — материал на vc.ru/Habr даст и трафик,
    и внешнюю ссылку).

## Что явно решено НЕ делать

- Не плодить шаблонные гео-страницы без уникального текста 300+ слов на район/город — прямой
  риск фильтра за неуникальный контент (аналог «Баден-Бадена», уже обсуждалось на примере
  проекта WashFix).
- Не индексировать черновики портфолио как есть. Сейчас у них `noindex` через GitHub Pages
  preview, но и на боевом домене публиковать заготовки с текстом «[Заполните: …]» нельзя —
  такие страницы нужно либо доделать, либо не публиковать.
