## Проект: ПЛАВИУМ — лидогенерация «3D-печать на заказ»

Цель сайта: сбор заявок на 3D-печать технических деталей и художественных фигурок, продвижение
в Яндекс.Поиске. Гео задано как Москва + доставка по всей России (areaServed в схеме включает
и город, и страну) — **точный регион и город не подтверждены пользователем**, уточнить перед
публикацией (см. «Незаполненные места»).

### Бренд и дизайн
Название и визуальный стиль — из готового бренд-макета пользователя, скопированного
2026-07-27 из внешней папки `D:\projects\3d_print\Marketplace_Disign_01_2025\OUT` в
[brand-source/](brand-source/) **внутри этого репозитория** — подробное описание всех
файлов, что использовано и что нет, и как повторить вырезку логотипа с прозрачностью —
см. [brand-source/README.md](brand-source/README.md). Тяжёлые исходники 3D-сцены
(`Logo.blend`, `.glb`, `Vizitrki.psd`, суммарно ~150 МБ) туда не копировались и остались
только во внешней папке — они не нужны для пересборки текущих веб-ассетов.

Кратко: имя **«ПЛАВИУМ»** (Plavium — игра слов «плавить» + суффикс как в «титаниум»),
золотой 3D-логотип на фоне инженерного чертежа. Из растровых рендеров (`crop.png`,
`3200_2048.png`, `Плавиум_кв.png`, `ComfyUI_00004_.png` — фон без текста) через
`scripts/optimize-brand-images.mjs` (Sharp) сделаны веб-версии в `public/brand/` и
`public/og-cover.jpg`. Скрипт читает исходники из `brand-source/` рядом со скриптом
(путь резолвится через `import.meta.url`, не хардкод) — работает из любого расположения
репозитория.

Палитра — `src/styles/global.css`: тёмно-синий «чертёжный» (`--color-dark: #1b2c4a`) + тёплое
золото (`--color-orange: #c9962e`, использовано и для акцентных кнопок, и как «--color-orange»
по историческим именам переменных) + кремовая бумага (`--color-bg: #f6efe0`). Переменные
называются по старым именам (`--color-orange`, `--color-violet`) от структуры, унаследованной
у `Site_stiralka` (WashFix, тот же владелец) — сохранены для единообразия кода между проектами,
но их **значения** перекрашены под бренд «Плавиум», а не буквально «фиолетовый/оранжевый».

**Известный класс бага, уже пофикшенный** — `.card` всегда белая независимо от секции;
`.section--dark` красит текст в светлый по умолчанию (для читаемости прямо на тёмном фоне), из-за
чего заголовки/текст внутри белых `.card`, лежащих в тёмных секциях, становились нечитаемыми
(белый на белом). Исправлено правилом `.section--dark .card { color: var(--color-text); }` —
**при добавлении новых блоков с `.card` внутри `.section--dark` дополнительных действий не
требуется, правило уже общее**, но если создаёте карточку с другим class-именем (не `.card`),
проверьте контраст текста на белом fone вручную.

**История экспериментов с hero-логотипом** (для контекста, если тема всплывёт снова):
1. Изначально — прямой прямоугольный кроп `crop.png` как есть (жёсткая рамка видна на фоне
   тёмной секции, выглядит как «приклеенная картинка»).
2. Пользователь попросил вырезать логотип без фона и наложить на чистый `ComfyUI_00004_.png` —
   сделано через альфа-вырезку по яркости из `no_fon/nofon (3).png` (чёрный фон), см.
   `brand-source/README.md` за деталями техники.
3. Пользователь попросил версию с тенью (по референсу `no_fon/nofon (2).png`) — тень
   сгенерирована синтетически (blur силуэта, не вытащена из чекерборда — см. README в
   brand-source), т.к. реальную тень с шахматного фона без alpha-канала вытащить нельзя.
4. Пользователь попросил вернуть **самый первый вариант** — откат до `crop.png` как есть.
   **Текущее состояние на момент этой записи: вариант 1 (обрезанный crop.png).** Рабочий код
   для вариантов 2 и 3 не удалён, доступен в истории git (`git log --oneline` — коммиты
   «Пересобрать hero-баннер» и «Добавить мягкую тень под логотипом»), можно поднять через
   `git show <hash>:scripts/optimize-brand-images.mjs`, если тема всплывёт снова.

### Стек и почему
Astro (статическая генерация) + Content Layer API (`src/content.config.ts`, коллекция
`portfolio`) — чтобы портфолио пополнялось добавлением markdown-файлов, а не правкой кода.
Node.js и GitHub CLI уже стояли в системе (winget, `C:\Program Files\nodejs`), но не были в PATH
сессии — при работе в новой сессии добавляйте `$env:Path += ";$env:ProgramFiles\nodejs;$env:APPDATA\npm"`
перед `node`/`npm`/`npx`.

### Что уже построено
- Главная (`src/pages/index.astro`) — хиро, буллиты доверия (опыт >1 года, крупные партии,
  2 типа принтеров, макс. размер детали), блок услуг (2 карточки), блок оборудования,
  блок «крупные партии» для B2B, тизер портфолио (3 featured-кейса), форма заявки, FAQ
  (микроразметка Schema.org `FAQPage`).
- Страницы услуг: `/uslugi/tehnicheskie-detali/` и `/uslugi/hudozhestvennye-figurki/` —
  раскрывают каждое направление отдельно для более широкого охвата поисковых запросов.
- `/oborudovanie/` — сравнение FDM и фотополимера (таблица + карточки), закрывает
  информационные запросы вида «FDM или фотополимер что лучше».
- Портфолио: `src/content/portfolio/*.md` (Content Layer API, `glob`-загрузчик) →
  `/portfolio/` (лента-грид) и `/portfolio/[id]/` (страница кейса, рендерит markdown-тело).
  Схема коллекции в `src/content.config.ts`: `title`, `client`, `date`, `category`
  (`tehnika`/`figurki`), `printerType` (`fdm`/`photopolymer`/`both`), `summary`, `cover`,
  `images[]`, `tags[]`, `featured`, `draft`.
- 3 карточки-заготовки с `draft: true` (бейдж «Черновик» на сайте): `sberbank.md` (реальный
  клиент, названный пользователем — специально оставлен как шаблон с инструкцией, а не
  заполнен придуманными подробностями, т.к. реальные детали заказа не были предоставлены),
  `tehnicheskiy-prototip.md` и `figurki-partiya.md` (общие примеры-заготовки для демонстрации
  формата ленты). **Прежде чем публиковать сайт — замените все три на реальные кейсы с фото.**
- `src/components/LeadForm.astro` — Имя + переключатель Телефон/Telegram/WhatsApp/Email,
  необязательное поле «что печатаем», чекбокс согласия, honeypot.
- Политика конфиденциальности (152-ФЗ, черновик — требует юридической проверки перед публикацией).
- SEO-инфраструктура в `src/layouts/BaseLayout.astro` — canonical, OG-теги, Schema.org
  `LocalBusiness`, автогенерация sitemap (`@astrojs/sitemap`), `public/robots.txt`.
- `src/lib/url.ts` — хелпер для внутренних ссылок с учётом `base` (нужен из-за потенциального
  временного деплоя на GitHub Pages по подпути, как в WashFix).

### Незаполненные места — обязательно доделать перед реальным запуском
1. **Регион и охват** — не подтверждён пользователем. Сейчас в `BaseLayout.astro`
   `areaServed` указывает и Москву (город), и Россию (страна) как компромисс. Уточните
   у владельца: только Москва (самовывоз/локальная доставка) или вся Россия (пересылка ТК) —
   от этого зависит гео-SEO стратегия (нужны ли гео-страницы районов/городов по аналогии
   с `Site_stiralka/src/pages/rayony/`).
2. `src/data/site.ts` — реквизиты-заглушки: телефон, email, ИНН, ОГРНИП, юрлицо, домен,
   Telegram/WhatsApp. Заменить на реальные данные.
3. Портфолио — все 3 кейса черновики (см. выше). Реальные фото положить в
   `public/portfolio/<slug>/`, пути указать в frontmatter (`cover`, `images`), снять `draft`.
4. Форма заявки — фронтенд-заглушка (показывает «Заявка принята», никуда не отправляет).
   Нужен бэкенд/интеграция (Telegram-бот, amoCRM/Bitrix24, Formspree) — отложено до выбора
   хостинга, как и в WashFix.
5. Фото цеха/принтеров/готовых изделий (кроме самого лого) — везде плейсхолдеры с пунктирной
   рамкой. Реальные брендовые рендеры логотипа уже подключены (`public/brand/`, hero-баннер
   на главной), но фото производства, готовых изделий и упакованных партий — нет.
6. Домен/хостинг не выбраны — `astro.config.mjs` использует placeholder `https://plavium.ru`
   (домен ещё не проверен на доступность/не зарегистрирован).
7. `og-cover.jpg` — сгенерирован из бренд-макета (`public/og-cover.jpg`, 1200×630 из
   `3200_2048.png`), но это тот же золотой логотип, что и в hero — для реального OG-превью
   в соцсетях/Яндексе может понадобиться отдельный вариант с товаром/фото, а не только вордмарк.

### Временный деплой (только для просмотра, НЕ для индексации)
- GitHub-репозиторий: https://github.com/Arhont1984/plavium-3d-print (публичный)
- Живой предпросмотр: https://arhont1984.github.io/plavium-3d-print/
- Деплоится автоматически через `.github/workflows/deploy.yml` при пуше в `main`.
- На этом адресе весь сайт помечен `noindex` (`BaseLayout.astro` включает это по переменной
  окружения `GITHUB_PAGES=true`, которую задаёт workflow при сборке) — чтобы Яндекс/Google не
  проиндексировали черновик вместо будущего боевого домена.
- Сборка под GitHub Pages вручную (PowerShell): `$env:GITHUB_PAGES="true"; npm run build`
- GitHub Pages включён через `gh api -X POST repos/.../pages -f build_type=workflow` — Settings →
  Pages в вебе тоже покажет источник «GitHub Actions».

### Приоритеты по контенту для SEO
Полный приоритизированный план (5 фаз: технический фундамент → быстрый контент → расширение
семантики → коммерческие сигналы → внешние сигналы) — отдельным документом:
**[SEO-PLAN.md](SEO-PLAN.md)**. Кратко по верхним пунктам: реальные фото портфолио, отзывы,
прайс-лист — дают максимум эффекта при минимуме усилий и не требуют решения по гео-стратегии
или домену.
